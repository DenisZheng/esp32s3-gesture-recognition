## 1. 实验概况

- 工作流：ESP32-S3 单模型 ESPDet-Pico 十类手部检测/识别；与 SSDLite、YOLOv10 手势工作流分开。
- 训练设备：RTX 4080 16 GB；软件版本固定为 PyTorch 2.2.0、torchvision 0.17.0、CUDA 12.1、Ultralytics 8.4.0。训练宿主的网络地址、账户和绝对路径不在仓库记录。
- 本轮从随机权重开始；不加载历史 checkpoint，不是断点续训。此前一轮在第 62 轮遇到宿主系统 RAM OOM，最后完整完成第 61 轮。
- 本轮是在完整十类数据集上新启动的 200 轮实验。训练集、验证集、测试集样本数为 **208,764 / 27,187 / 45,418**，合计 **281,369**；模型输入仍为 224×224。
- 原数据集和签核材料仅在授权的本地训练环境中使用。当前记录的许可范围仅为研究训练，不表示全量逐图审核或商业授权。

## 2. 修复内容

本次定位到的一个确定缺陷是 Ultralytics 8.4.0 读取损坏或缺失数据缓存时，异常路径可能没有恢复 Python GC 状态。补丁通过 `try/finally` 恢复调用前状态，并保留原本已关闭 GC 的情形。

另外，P2 训练入口新增了独立 train/val workers 和 prefetch 配置：

- `scripts/p2_loaders.py`：训练仍用 `InfiniteDataLoader`，验证用有限 `DataLoader`；显式关闭不再使用的迭代器和 worker。
- `patches/ultralytics-8.4.0.patch`：只针对固定版本 `8.4.0`，包含缓存 GC 恢复、loader 生命周期与 prefetch 参数改动。
- `scripts/apply_ultralytics_patch.py`：应用补丁前核对版本；已应用时可重复检查，不匹配时停止。
- `docker/Dockerfile.p2-espdet-cu121`：构建镜像时应用补丁；数据、私有签核和 checkpoint 通过运行时挂载，不复制进镜像。

上游参考及改动边界见 [Ultralytics 补丁说明](P2_ULTRALYTICS_PATCH.md)。本次没有修改模型结构、损失函数、优化器、batch、输入分辨率、增强、类别编号或数据划分；P2 CLI 仍没有真正的 `--resume` 入口。

- 在旧环境中复现了缓存读取异常后 GC 状态未恢复的问题；修复镜像包含针对性补丁。

## 5. 复现与进度检查说明

以下路径均为占位符；操作人员应在获准的 Linux 训练环境中使用本机配置的数据目录和运行目录，不要把私有绝对路径、SSH 主机信息或签核材料写入公共文档。

```bash
# 在固定版本的独立 P2 Docker 环境构建
docker build --progress=plain \
  -f docker/Dockerfile.p2-espdet-cu121 \
  -t <本地镜像标签> .

# 复现本轮 worker 设置时要显式传入 2/0；不要重启仍在运行的实验。
python -m scripts.p2_train train \
  --data <已获准数据集的 dataset.yaml> \
  --model-yaml <模型配置> \
  --run-dir <独立实验目录> \
  --epochs 200 --batch 8 --imgsz 224 --device 0 --optimizer SGD \
  --workers 2 --val-workers 0 --prefetch-factor 2 --val-prefetch-factor 1
```
